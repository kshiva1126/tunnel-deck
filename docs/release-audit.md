# Release license, security, and resource audit

This is the pre-publication audit record for GH-50. It audits base commit
`738e21bee70f599c2eed2d09815c4bd5948bf10e` plus the focused notice-generation,
packaging, test, and documentation changes in GH-50. The eventual review commit
is recorded by the trusted publication hook; putting its hash in its own content
would make the commit circular.

Audit date: 2026-09-22. Local environment: Linux x86_64, kernel
7.0.0-31-generic, Rust 1.85.0 (4d91de4e), Cargo 1.85.0, and cargo-audit
0.22.1. Native macOS and packaged-artifact checks are listed separately below
and are not inferred from this Linux run.

## Result and severity

No unresolved high- or critical-severity finding was identified. Release
archives now contain both TunnelDeck's MIT `LICENSE` and generated
`THIRD_PARTY_LICENSES.txt`. The latter inventories every Cargo package reachable
for any of the four release targets and retains the license/notice files shipped
by those packages. Generation fails if metadata has no license declaration or a
package supplies no license/notice file.

Two RustSec soundness warnings affect `lru 0.12.5`, reached through
`ratatui 0.29.0`. RUSTSEC-2026-0002 requires use of `LruCache::iter_mut`;
RUSTSEC-2026-0253 requires `LruCache::pop` with a key whose destructor panics,
followed by cache mutation. Ratatui's layout cache does not invoke those methods,
and its `(Rect, Layout)` key does not have a user-defined destructor. These
preconditions are not reachable through TunnelDeck's use, so this is accepted
as low residual risk rather than an exploitable release finding. Upgrading to
ratatui 0.30 was rejected because it requires Rust 1.86 or later, conflicting
with the agreed Rust 1.85 baseline. The unmaintained `paste 1.0.15` warning is
also transitive through ratatui and is a maintenance risk, not a vulnerability.
Re-evaluate both when the toolchain baseline or TUI dependency is intentionally
upgraded.

distribution notice stale.

## Code review against the threat model

| Area | Implemented control and evidence | Finding |
| --- | --- | --- |
| IPC permissions and framing | Private owned 0700 runtime directory; owned 0600 lock/socket; socket type/owner/mode verification; 1 MiB newline-JSON frames; five-second read/write deadlines; request ID/version checks; subscriber queue of 64 with disconnect on lag. Protocol and lifecycle tests cover unsafe paths, malformed/oversized input, timeouts, correlation, and lag. | No high/critical finding. The daemon creates one OS thread per accepted connection with no application-level global connection cap. Current-user-only access and OS FD/thread limits bound cross-user exposure, but a malicious process under the same account can cause resource pressure. Residual severity: medium; hardening should add a bounded worker/connection budget without changing IPC v1. |
| Configuration storage | The daemon is the sole writer. Descriptor-relative no-follow operations require owned 0700 directories and owned single-link 0600 regular files. Saves validate first, write an exclusive temporary file, flush, rename atomically, and sync the directory; migration backs up and syncs exact original bytes first. | No high/critical finding. Abandoned private temporary/backup files have no automatic count/age retention; only the sole writer may explicitly remove a known temporary. Residual severity: low. |
| Diagnostic secrecy | SSH stderr capture is fully drained and capped at 64 KiB. Clients and logs receive fixed classifications, never raw stderr, rule endpoints, credentials, or environment values. Synthetic-secret behavior tests cover failure and reconnect paths. Log records are single-line. | No finding. Classification examines bounded raw stderr in guardian memory before discarding it. |
| Logs | Owned single-link 0600 files under an owned 0700 descriptor-held directory; unsafe active or rotation objects fail closed. Rotation is serialized, capped at 1 MiB with three backups, and preserves at most approximately 4 MiB total. | No finding. Logging failure is observational and cannot undo tunnel state. |
| SSH command and host-key policy | Direct argv execution without a shell; validated aliases cannot become options; private master and control socket per attempt; `BatchMode=yes`; no `StrictHostKeyChecking=no`; host-key settings remain OpenSSH-owned. | No finding. Interactive password/passphrase authentication remains intentionally unsupported. |
| Signals, cleanup, descriptors, and processes | A guardian owns one master attempt. Lease EOF triggers process-group SIGTERM, five-second grace, SIGKILL, reap, attempt-directory removal, then inherited lock release. FD_CLOEXEC is restored before SSH. Stop/start races use attempt identity and cancellation. Fake-process and isolated OpenSSH tests exercise large stderr, concurrent stop, forced termination, daemon SIGKILL cleanup, listener closure, and lock release. | No high/critical finding. Simultaneous daemon and guardian failure and deliberately detached descendants remain outside the documented guarantee. Rule/guardian count is not application-capped, so a same-user configuration can approach OS process/FD limits. Residual severity: medium; add a maximum concurrent-attempt policy in a separate compatibility-reviewed change. |
| Discovery and path traversal | Include recursion is capped at 32 levels and 256 files; SSH query output is bounded; query/connection deadlines are applied; socket path length is target-specific. | No finding. Individual SSH config file size and IPC request count per connection are not application-capped; local filesystem and same-user trust limit exposure. Residual severity: low/medium resource hardening. |
| TUI terminal cleanup | RAII restores raw mode, alternate screen, and cursor on normal/error returns; panic hook and SIGINT/SIGTERM/SIGHUP paths request restoration. | No Linux code-review finding. Native macOS and human terminal checks remain pending. |

The medium resource-limit gaps do not allow another OS user to access the
private service and are ultimately bounded by per-user/system limits. They are
not release-blocking high/critical findings, but must remain visible rather than
being described as solved.

## Native and human checks not performed here

- No packaged release archive was executed on Linux x86_64/aarch64 or macOS
  Intel/Apple Silicon. The release manifest must continue to say
  `native_smoke_test.status = not_run` until those checks occur.
- This Linux run does not validate macOS 13, Intel macOS, Apple signing,
  notarization, Gatekeeper behavior, native descriptor/flock semantics, or
  terminal/browser behavior. Follow `docs/macos-validation.md`.
- No personal SSH configuration, external SSH account, credential, signing key,
  or GitHub token was used. Existing disposable OpenSSH probe evidence is prior
  evidence, not a new GH-50 native run.
- `cargo audit` is a RustSec database check, not source-level proof that all
  malicious-input or supply-chain behavior is absent.

Remote Linux/macOS CI and release-artifact smoke remain post-publication human
review conditions. Their absence before publication does not change the local
audit result and must not be reported as a pass.
